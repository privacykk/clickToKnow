# ClickToKnow 人工验收清单

适用于无法用单测覆盖的路径：真实辅助功能授权、真实前台应用、真实剪贴板、菜单栏与弹窗交互。
单测已覆盖的纯逻辑不再重复列（见 `Tests/ClickToKnowTests/`）。

前置：打包成 `.app` 并执行 `./Scripts/make_signing_cert.sh` 固定签名（裸 `swift run` 的授权行为不代表真实场景）。
每个场景前请在「状态总览」确认：辅助功能已授权、当前 API 配置为「可用」。

## A. 取词主路径（问题 5）

| # | 场景 | 期望 |
|---|---|---|
| A1 | Safari 选中英文单词 → `⌥⌘K` | 弹窗贴选区左上角，释义出现；剪贴板内容不变（AX 路径不碰剪贴板） |
| A2 | VS Code 选中代码标识符 → `⌥⌘K` | 同上；释义贴合代码语境（上下文生效） |
| A3 | 目标应用 AX 无响应（大型 Electron 文档 / 远程桌面 / 受保护 PDF） | 菜单栏与设置窗口**保持可交互**（主线程不再阻塞）；最迟约 0.5s 后回退复制或给出「抓取超时」 |
| A4 | 上述慢应用里快速连按 `⌥⌘K` 五次 | 只产生一次查询；不出现多份弹窗；活动监视器里本进程线程数不持续增长 |
| A5 | 慢应用等待期间切换到别的应用，再切回 | 若等待期间前台已变化，应提示「已跳过本次查询（前台应用已切换）」，且不复制新应用的内容 |
| A6 | 焦点在密码框 → `⌥⌘K` | 提示「已跳过本次查询（安全输入）」；剪贴板不变 |
| A7 | 1Password / 钥匙串访问中选中文本 → `⌥⌘K` | 提示「已跳过本次查询（黑名单应用）」 |

## B. 剪贴板兜底事务（问题 6）

| # | 场景 | 期望 |
|---|---|---|
| B1 | 在不支持 AX 的应用里选词 → `⌥⌘K`，先复制一段自定义内容作为「原始剪贴板」 | 取词成功后剪贴板恢复为那段原始内容 |
| B2 | 连续两次取词，间隔 < 300ms | **最终剪贴板仍是原始内容**，不会被污染成第一次查到的词 |
| B3 | 兜底期间用第三方剪贴板工具（Paste / Raycast 历史）写入内容 | 脚本不覆盖第三方内容；本次查询按当时读到内容处理，不得把第三方内容当成选词 |
| B4 | 目标应用禁止复制（部分 PDF） | 0.5s 后提示「抓取超时」，剪贴板保持原样 |
| B5 | 复制成功但选区为空 | 提示「未抓取到文本」，剪贴板保持原样 |

## C. 弹窗交互（问题 7 + 流式合并）

| # | 场景 | 期望 |
|---|---|---|
| C1 | 弹出释义后，Safari 保持前台，按 `Esc` | 弹窗关闭（原应用同时收到这次 Esc，属已知行为，见 README「已知限制」） |
| C2 | 焦点在本应用设置窗口时按 `Esc` | 弹窗关闭且不产生二次响应 |
| C3 | 鼠标停在弹窗上接收长流式内容（>15s） | 弹窗**不会**在悬停期间自动关闭；移开鼠标后重新开始计时 |
| C4 | 长流式内容（>500 字）观察滚动与重排 | 内容流畅追加、无闪烁跳位；主线程不卡（可同时移动鼠标验证） |
| C5 | 弹窗显示期间点击外部 | 弹窗关闭，在途请求被取消（不再出现「关窗后又弹出来」） |
| C6 | 词典兜底查询中立即关窗（Esc / 点击外部） | 弹窗**不再**重新出现（此前 detached 任务会把它弹回来） |
| C7 | 流式过程中暂停取词 | 后续增量不再更新弹窗，也不再写历史 |

## D. 错误与日志脱敏（问题 9）

| # | 场景 | 期望 |
|---|---|---|
| D1 | 填一个错误的 API Key（`sk-` 开头）→ 测试连接 | 提示里显示 HTTP 401 与错误码，但**不出现完整密钥**（应为 `***`） |
| D2 | 用一个会回显请求内容的代理（如回显 Authorization 的网关） | 弹窗与设置页提示不包含密钥原文 |
| D3 | `log show --predicate 'subsystem == "ClickToKnow"'` | 失败日志只有类别与状态码（如 `server(status=401)`），无服务端正文 |

## E. 密钥隔离（问题 1 / 2）

| # | 场景 | 期望 |
|---|---|---|
| E1 | 配置 A 可用 → 新建配置 B，密钥留空，填别的域名 → 测试连接 | 请求**不带** A 的密钥（服务端返回缺鉴权错误），提示不再显示 A 的掩码 |
| E2 | 编辑已有配置，把 Base URL 改成另一台主机 | 密钥提示变为「端点主机已变更，请重新输入」；测试/拉取不沿用旧密钥 |
| E3 | A、B 各存一份不同密钥，来回切换生效项 | 「大模型」页每行掩码与状态总览始终对应各自配置，不串 |
| E4 | 沙盒/签名问题导致钥匙串不可用（ad-hoc 裸跑）→ 保存密钥 → 切到另一个配置 | 新配置显示「缺少密钥」，A 的密钥不会跟随切换 |
| E5 | 删除某个配置 | 该配置的钥匙串条目与其遗留存储一并清除（`security find-generic-password -s ClickToKnow -a profile-<uuid>` 查不到） |

## F. 缓存与配置（问题 3）

| # | 场景 | 期望 |
|---|---|---|
| F1 | K8s 文章查 `helm`，再在航海文章查 `helm` | 两次释义不同（上下文参与缓存键） |
| F2 | 先不填密钥查词（走词典），再补密钥查同一词 | 第二次走 LLM，不再命中词典结果 |
| F3 | 查 `US` 与 `us` | 分别请求、分别返回（大小写不合并） |
| F4 | 切换 API 配置后重复查同一词 | 重新请求（配置变更清空缓存） |

## G. 历史记录（工程项 2）

| # | 场景 | 期望 |
|---|---|---|
| G1 | 连续查询 20 次，同时移动鼠标/滚动弹窗 | 无卡顿（写入已移到后台） |
| G2 | 查询后立即退出应用，重新打开看历史 | 最后几条记录仍在（退出前 flush） |
| G3 | 手动把 `~/Library/Application Support/ClickToKnow/history.json` 改成非法 JSON 后启动 | 原文件被备份为 `history.corrupt-<时间戳>.json`，历史窗口顶部出现橙色告警；新查询正常写入 |
| G4 | 导出 CSV / Anki TSV（含逗号、引号、换行的释义） | 转义正确，导入 Anki 无错行 |

## H. 卸载（问题 10）

| # | 场景 | 期望 |
|---|---|---|
| H1 | `./Scripts/uninstall.sh --dry-run`（有 2+ 个配置与历史记录） | 逐条打印每个 `profile-<uuid>`、`apiKey`、domain、应用路径、history.json 路径；**不改动任何东西** |
| H2 | 在可丢弃的机器上执行 `./Scripts/uninstall.sh` | 应用移除、配置清除、钥匙串无残留；history.json 保留并打印路径 |
| H3 | 同上加 `--purge` | history.json 与 `~/.clicktoknow` 一并删除 |
| H4 | 卸载后检查「系统设置 → 登录项」与「隐私与安全性 → 辅助功能」 | 脚本会提示需手动清理的残留项（TCC 与 SMAppService 无法脚本化） |

## I. 发布门禁（工程项 5）

| # | 场景 | 期望 |
|---|---|---|
| I1 | 推送一个测试 tag（如 `v0.0.0-test`） | Actions 里 `verify`（build + test）先跑，通过后才执行 `build-release` |
| I2 | 让测试失败的分支打 tag | Release 流程在 `verify` 处失败，不产出安装包 |
| I3 | 对已有 Release 重跑发布 | 同名产物被覆盖；旧版本号附件被删除；全程 Release 不为空 |

## 待补验证（本轮无法在 CI/本机确认）

- macOS 13 最低版本与 Intel（x86_64）实机：需在对应机器或 runner 上跑一遍 A1/A2/B1/C3 与 `./Scripts/package.sh`。
- 真实钥匙串授权被拒时的删除复验（H2）需在隔离账号下操作，避免影响日常钥匙串。
